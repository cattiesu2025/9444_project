# 自然遮挡子集（测试集 IR query）

负责人：A。用途：服务 L（局部监督，q=2 上下两区）与 E 的鲁棒性报告。设计文档 §7.3 要求"自然样例单列，不把人工扰动称为真实遮挡分布"；E 的人工遮挡是固定位置的中性色块，本子集补充**真实场景中的遮挡**。

文件：`natural_occlusion_test_ir.csv`。只含相对路径与标签，不含任何图像。

## 范围

最初计划只在验证集上标注。2026-11-07 按下文标准逐张检查了**验证集全部 1,980 张 IR query**（99 人，全部来自室内 cam3），结果**没有一张符合标准**：被物体或他人遮挡为 0；画面截断超过约 10% 的也为 0，只有少数头顶或肩侧被裁掉一点（约 10 张，均未达标准）。验证集是单人走廊场景，无法提供自然遮挡样例。这本身是一项 EDA 发现：开发阶段的遮挡分析只能依靠人工遮挡。

经小组决定，自然遮挡子集改为定义在**测试集的 IR query**上：96 人、3,803 张，其中 cam3（室内）1,883 张、cam6（室外）1,920 张。

**初标结果（2026-11-07，待 A 复核）**：224 张、73 个身份。

| 分组 | 数量 |
| --- | --- |
| 摄像头 | cam6 219 张；cam3 5 张（室内走廊，门框或墙边挡住身体一侧） |
| 遮挡来源 | 物体 208（大多为室外大立柱，其次是桌椅）；其他行人 16；画面边缘 0 |
| 区域 | 左右一侧纵向遮挡 `side` 159；下部遮挡 `bottom` 65（几乎都是桌椅挡腿） |
| 半区 | `both` 158；`lower` 65；`upper` 1 |
| 程度 | `mild` 155；`heavy` 69 |
| 待复核 | 4 张接近 10% 下限，note 中标有"待复核" |

主要观察：自然遮挡几乎全部来自室外 cam6 的立柱和桌椅，形态以**纵向一侧遮挡**为主；这与 E 的人工遮挡（水平的上/中/下色块）不同，只有桌椅挡腿一类接近"下部遮挡"。上半身被挡的样例几乎没有。

使用测试集的规则（设计文档：测试标签仅用于冻结后的最终评估，不得用测试结果改方法）：

1. 配置已于 10/31 冻结。标注只看图像，在**任何人看到模型的测试集结果之前**完成，并提交到 Git。评价脚本会拒绝使用有未提交修改的标注文件，并在结果中记录标注文件的提交号。
2. 子集只用于最终的**描述性报告**，不用于选模型、调参或修改方法。
3. 不标注 RGB gallery，与 E 的协议一致：只看 query 端的退化。

## 判定标准（标注前固定）

一张图计入子集，当且仅当**目标人物本应出现在裁剪框内的身体部分**，被下列之一挡住，且被挡部分约占人体的 10% 以上：

| `occluder` | 含义 | 不算 |
| --- | --- | --- |
| `object` | 被物体挡住：桌椅、栏杆、门框、柱子、植物、车辆等 | 人物自己拿着的包、伞、手机 |
| `person` | 被另一个人挡住 | 背景中另一个人与目标不重叠 |
| `frame_edge` | 人物被画面或裁剪框边缘截断：缺头、缺脚、半个身子在框外 | 只缺一点手指、鞋尖等不到约 10% 的部分 |

不因下列原因计入（这些属于其他难点，单独分析）：只是暗、模糊或低分辨率；姿态特殊或侧身；与他人相近但未重叠。

其余字段：

| 字段 | 取值 | 说明 |
| --- | --- | --- |
| `region` | `top` / `middle` / `bottom` / `side` | 被挡部分在图中的位置；`side` 表示左右边缘的纵向截断。前三类与 E 的人工遮挡带对应 |
| `half` | `upper` / `lower` / `both` | 被挡部分落在图像上半还是下半，对应 L 的 q=2 两个局部区域；跨越中线时为 `both` |
| `severity` | `mild` / `heavy` | 约 10–25% / 超过 25% 的人体被挡 |
| `note` | 文本 | 简短描述，如"桌子挡住小腿" |

一张图如果同时有多种遮挡，按**被挡面积最大**的来源记一行。

## 标注流程与可复核性

1. `python scripts/occlusion_review_sheets.py --mode all`：把测试集每个身份的全部 IR query 拼成一张图，图下标序号，逐张按上表判断。
2. 初标由 A 借助 AI 助手（Claude）逐张完成，再由 A 用 `--mode subset` 生成的分组拼图逐条复核，修改或删除不符合标准的条目。
3. 复核完成后才把列表交给 L/E 使用。标注版本以 Git 提交为准；评价脚本会把 CSV 的 sha256 写入结果。

## 解读限制

- 子集是按遮挡**有目的地挑选**的，样本量小，只能做描述性对比，不代表总体遮挡分布，也不做显著性结论。
- 遮挡样例可能集中在室外 cam6；cam6 本身也可能比 cam3 更难，所以应同时报告 cam6 未遮挡 query 的结果作对照。
- 遮挡样例往往同时更暗、更小或姿态更特殊，子集表现差不等于"遮挡导致"。比较同一子集上不同模型的差值（例如 M2−M0）比看绝对值更有意义。
- 与人工遮挡结果分开报告。
